# Contributing to Markdown-Magic

Thanks for your interest. Markdown-Magic is in active development, so this page tells you what's welcome right now and what isn't — please read it before opening issues or pull requests.

## Reporting bugs

**Bug reports are always welcome.** If you hit something broken, unexpected, or that could lose your work, open an issue using the bug report template at <https://github.com/ALi-strg/markdown-editor/issues/new/choose>. A good report includes:

- Your OS and architecture (e.g. Windows 11 x64, macOS 14, Ubuntu 22.04).
- The version you're running — the release tag (e.g. `v1.1.3`) if you installed a bundle, or the commit if you built from source.
- Steps to reproduce, and what you expected versus what happened.
- Screenshots, and whether the problem is reproducible across restarts.

## Asking questions

Questions are fine as issues too — open one and ask. There are no Discussions enabled; everything flows through the issue tracker.

## Code contributions (pull requests)

**Pull requests are not accepted at this stage.** The codebase is changing fast — internal structure, behavior, and even the document model shift between releases — so a PR written against today's code will likely be outdated before it can be reviewed. PRs from outside the Code Owner's Collaborator circle are therefore closed without merging. This policy will be revisited once the project stabilizes; it will be announced in the README when it changes.

If you're tempted to send a PR with a fix, please file a bug report or a detailed issue instead — the Code Owner reads every issue and will fix it (or incorporate the idea) in their own time.

## Thank you

Bug reports — even one-line ones — genuinely make this project better. Thank you for taking the time.
