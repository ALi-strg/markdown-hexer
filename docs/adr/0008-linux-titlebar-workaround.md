# Linux-only titlebar workaround (remove when tao 0.36 ships)

`set_document_title` applies a Linux-only workaround on top of the existing `window.set_title(...)`: `title::sync_csd_titlebar` (`src-tauri/src/title.rs`) also sets the GTK client-side-decorations header bar's title, because on a Wayland session tao 0.30.3+ (PR #979) installs a custom `GtkHeaderBar` that `gtk_window_set_title()` does not update — `Gtk.Window:title`, the taskbar, and `Window.title()` change, but the visible header bar keeps the title from `tauri.conf.json` forever (tauri-apps/tauri#13749; upstream defect tauri-apps/tao#1046). The trade-off was workaround-now versus wait-for-the-fix: tao PR #1218 (merged 2026-06-29, released in tao 0.36.0) mostly reverts #979 so GTK's default CSD binds the header bar title to `Gtk.Window:title` again, but no stable Tauri release ships it yet (tauri 2.11.5, 2026-07-01, pins tao 0.35.3) and there is no stable release date — so the workaround ships now to keep the Window Title contract (`<filename> * — Markdown-Magic`) honest on Wayland Linux, at the cost of a hack that must not outlive the upstream fix. It is the exact app-level pattern validated against tauri#13749 and is defensive by contract: the chain runs inside `run_on_main_thread` (GTK3 widgets are only safe on the GTK main thread) and each step — `titlebar()` returning `None` (X11 / server-side decorations), the downcast to `GtkHeaderBar` failing (tao structure differs), or the main thread shutting down — is a silent no-op, never a panic. The webview `document.title` is deliberately not part of the workaround: on WebKitGTK wry never propagates the webview title to the GTK window, so `document.title` and the native titlebar are fully decoupled on Linux (and were never coupled on any platform in stock Tauri) — `document.title` keeps feeding the WebDriver "Get Title" assertions (the webview title is otherwise invisible — Tab labels derive from the filename, not the webview title), and the native titlebar is set only by this command. **Removal tracking:** drop `sync_csd_titlebar` and the Linux-only `gtk` dependency when a stable Tauri release pulls in tao 0.36; watch tauri-apps/tauri#13749 and tauri-apps/tao#1046 — the workaround masks that fix. **Verification:** no automated seam can exercise the broken path, so the only real-machine validation is manual — the next release's .deb on the reporter's Wayland host must show the opened filename, the Tab-switched name, and the Dirty asterisk in the native titlebar; WebDriver "Get Title" reads `document.title`, which was never wrong (the E2E suite is green because of the bug), and CI runs under xvfb (X11, server-side decorations), where `titlebar()` is `None` and the bug does not manifest.
