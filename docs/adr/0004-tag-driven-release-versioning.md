# Tag-driven release versioning and asset naming

Releases are tagged `v1.0.x`, but the version baked into every bundle came from the static manifests (`0.1.0`), so a `v1.0.3` release shipped `Markdown-Magic_0.1.0_*` assets that were also indistinguishable across platforms. The Version is now resolved from the triggering git tag at build time (leading `v` stripped, prerelease tags like `v1.1.0-rc.1` flag the Release as prerelease) and injected as `--config {"version": ...}` rather than by mutating the manifests, so the manifests keep a static dev version that never ships and there is no version drift to manage. Uploaded assets are renamed via tauri-action's `releaseAssetNamePattern` to `Markdown-Magic_<version>_<platform>-<arch><setup>.<ext>` with the platform written literally (`windows` / `macos` / `linux`) because the action's `[platform]` placeholder yields `darwin`/`linux`. `productName` is deliberately left untouched: the MSI upgrade code is derived from it, so overriding it per platform would silently break upgrades of already-installed MSI packages. Historical releases keep their original asset names.
