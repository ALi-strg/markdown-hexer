# Flatpak distribution via GitHub Releases

The app ships a Flatpak Bundle — a single-file `.flatpak` attached to the GitHub Release and installed with `flatpak install` — built from the release `.deb` inside a pinned GNOME runtime (org.gnome.Platform + org.gnome.Sdk), rather than publishing to Flathub or hosting a private Flatpak repository. Flathub was rejected because it requires a public source repository and the repo is deliberately private (this may be revisited if the repo ever goes public); a self-hosted Flatpak repo was rejected as infrastructure that adds hosting and update-management burden for a one-product release. The bundle's sandbox opens `--filesystem=home` instead of staying portal-only because the Preview Pane resolves relative images against the opened Document's directory over the `asset://` protocol, and portal file access grants only the chosen file, not its siblings — a tight sandbox would silently break relative-image rendering. The aarch64 bundle is produced by a parallel native ARM job so both Linux architectures ship.
