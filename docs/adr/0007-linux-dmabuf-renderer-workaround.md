# Unconditional WEBKIT_DISABLE_DMABUF_RENDERER on Linux

`main()` sets `WEBKIT_DISABLE_DMABUF_RENDERER=1` unconditionally on Linux, before the Tauri Builder starts. On some hosts — most often NVIDIA GPUs, and on Wayland — WebKitGTK's DMABUF renderer produces a blank/white window with no error (tauri-apps/tauri#9394); the CI's own E2E run already needs the same flag for its headless webview. This trades WebKit's accelerated compositing path for reliable rendering on affected hosts, and applies to every Linux bundle equally (.deb, .rpm, .AppImage, Flatpak) because the defect is host-GPU, not packaging — the original report blamed the AppImage, but the `.deb` on the same machine would fail identically. It disables only the DMABUF fast path, not compositing, and was chosen over `WEBKIT_DISABLE_COMPOSITING_MODE` (a last resort that disables accelerated compositing entirely) and over gating the override on the AppImage via the `$APPIMAGE` env var.
