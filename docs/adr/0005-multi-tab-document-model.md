# Multi-Tab workspace replacing the single-Document model

The app previously held exactly one Document in memory (ADR-0003, which explicitly rejected multi-tab editing); that model is now reversed: the app holds many Documents, one per Tab with a one-tab-per-path invariant, the Layout Mode (Split / Preview / Focus) is a property of each Document while Theme, Font, and Text Size stay app-wide, and background Tabs render cold. Each Tab preserves its editor cursor, scroll, undo, and Find state for the session, the Confirm-Discard Guard now guards Tab close and app close (once per Dirty Tab) rather than New/Open, and neither Tabs nor modes persist across launches. Multi-Tab was chosen because the single-Document window forecloses side-by-side file comparison and the multi-file workflow desktop editors assume; the cost is a non-flat state model (a Tab list plus an Active index), per-Tab CodeMirror state preservation, and an `asset://` scope that must follow the Active Document's directory.
